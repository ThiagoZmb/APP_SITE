Spec aprovada: `docs/superpowers/specs/2026-11-27-epis-design.md`. Referência funcional: o piloto `epi.html` (apagado no fim; fica no histórico do git).

1. `calculo/epis.js` + `test/epis_calculo.test.js`: validação do EPI, da entrada, da entrega (data hoje por padrão, passada sim, futura não; inteiros; C.A. só números), motivo, chave; saldo, "Dura (est.)" e Resumo do piloto.

4. `epis.html` + `epis.js` + `test/epis_tela.test.js`; menu e `PAGINAS` em `layout.js` (subir o `?v=` do layout em todas as páginas).
5. Apagar `epi.html`; `docs/regras/epis.md`; `CLAUDE.md`; `npm test`; conferir a tela no Edge headless com API simulada.

## Tabelas

- `web_epis` (nome único, ca, minimo, ativo)
- `web_epi_entradas` (epi_id, quantidade, chave única)
- `web_epi_entregas` (funcionário e nome copiado, data_entrega, observacao, chave única, cancelamento)
- `web_epi_entrega_itens` (entrega_id, epi_id, nome e C.A. copiados, quantidade)
- `web_epi_fotos` (entrega_id, mime, dados, chave única por entrega, removida_em)

## Rotas

| Rota | Permissões |
|---|---|
| `GET /epis` | epi.ver |
| `GET /epis/funcionarios` | epi.ver, epi.registrar |
| `GET /epis/resumo` | epi.ver, administrativo.ver |
| `GET /epis/entregas`, `GET /epis/entregas/:id/foto/:fotoId` | epi.ver |
| `POST /epis/entregas`, `PUT /epis/entregas/:id/foto` | epi.ver, epi.registrar |
| `POST /epis`, `PUT /epis/:id`, `POST /epis/:id/entrada`, `POST /epis/entregas/:id/cancelar`, `DELETE /epis/entregas/:id/foto/:fotoId` | epi.ver, epi.gerir |

## Concorrência

Entrega: numa transação, primeiro `SELECT ... FROM web_epis WHERE id IN (...) ORDER BY id FOR UPDATE` (ordem fixa; nenhuma leitura comum antes, para a foto consistente do InnoDB nascer depois da trava), depois a chave de envio, o funcionário, o saldo e só então os INSERTs. Entrada trava o EPI; cancelar, anexar e remover foto travam a entrega.
