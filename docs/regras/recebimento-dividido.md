# Recebimento dividido em várias formas de pagamento (financeiro.html)

- **O que é**: na gaveta "Novo movimento" de uma **Entrada nova**, o bloco "Dividir em mais formas" permite receber o mesmo pedido em mais de uma forma (ex.: Pix + cartão) numa operação só. A forma de cima é a primeira; as outras são linhas extras (forma, banco, valor, data, situação). Dados comuns (cliente, pedido, PDV, pré-nota, nota fiscal, categoria, observação) valem uma vez. Edição de lançamento existente continua uma linha por vez.
- **Gravação** (`rotas/fluxo_varios.js`, validação pura em `calculo/fluxo_varios.js`): `POST /fluxo/salvar_varios` (`financeiro.lancar` + `valores.ver`). 2 a 10 linhas, só `Entrada`, situação de entrada (Recebido, A Receber, Faturado, Protestado, Atrasado), valor > 0. **Tudo ou nada** numa transação; IDs em sequência a partir de `MAX(ID)` travado com `FOR UPDATE`; `INSERT` simples (nunca sobrescreve; colisão de ID = 409 "Nada foi salvo"). Cada linha é uma linha normal de `fluxo_de_caixa`, como o VB grava.
- **Soma das linhas = só aviso**, nunca bloqueia (decisão do dono, 2026-11-10).
- **Restante automático (a partir de 2026-11-10, decisão do dono)**: quando a gaveta abre pelo botão **Receber** da ficha do cliente (`clientes.html` → `financeiro.html?novo=entrada&totalPedidos=&credito=&entrega=`), o topo mostra o **total dos pedidos selecionados**; o campo Valor é o que entra agora. Se for menor que o total (já sem o crédito) e a linha de cima for `Recebido`, a tela gera sozinha uma linha **`A Receber`** com o restante, forma e banco em branco e vencimento = **maior `DATA_PRONTO`** dos pedidos marcados (editável antes de salvar). Vai pelo mesmo `/fluxo/salvar_varios` (a forma só pode ficar em branco em linha `A Receber`). Valor igual ao total: uma linha só; maior: aviso, sem bloquear.
- **Pedido vira Recebido quando há restante** (substitui a regra antiga de deixar `A Receber`): senão o saldo do cliente contaria o TOTAL do pedido mais a linha `A Receber` (em dobro). A ficha recebe `restante: true` no aviso `salvo` e chama `/clientes/receber` com `marcarRecebido` forçado. Sem restante vale a escolha do usuário na pergunta.
- **Cancelar a gaveta não grava nada**: `/clientes/receber` (pedidos Recebido e crédito zerado) só roda depois do aviso `salvo` (`recebimentoPendente` em `clientes.html`); `fechado` descarta.
- **Receber o restante depois**: a linha `A Receber` aparece no Financeiro do cliente; mudar para `Recebido` pelo menu "Alterar para" (ou editar a linha). O botão Receber só trabalha com pedidos marcados.
- **Resumo do pedido** (`GET /fluxo/pedido_resumo?numero=`, `financeiro.ver` + `valores.ver`, só leitura): total, já recebido (soma das linhas `Recebido` cujo campo PEDIDO é **exatamente** esse número) e falta. Só com um único número de pedido; `23376/23316` não calcula (não dá para saber como o valor se divide).
- **Quitar**: caixinha "Pedido quitado: marcar como Recebido" (vem marcada quando o recebido cobre o total; linhas `A Receber` não contam). Fora do botão Receber da ficha (sem restante automático), marcada, `ped_orc.FINANCEIRO` vira `Recebido` na mesma transação (**escrita em tabela do VB**, mesma regra do `/clientes/receber`); exige `clientes.receber`, um único número de pedido existente.
- **Front**: `fluxo_divisao.js` (contas puras testadas no Node + ligação da tela). **Não testado no navegador real.**
